## Format decision

**Use regular skills for all nine command entry points.** OpenAI explicitly recommends turning Claude Markdown commands into skills. Codex has built-in slash commands, but its legacy Markdown custom prompts are deprecated and stored in the user’s Codex home rather than shared through repositories. They are unsuitable as this edition’s distribution format. [Claude plugin migration](https://developers.openai.com/plugins/guides/submit-claude-plugin), [custom prompts](https://learn.chatgpt.com/docs/custom-prompts).

There is a native *importer*, not an equivalent command runtime. In 0.159.3 it migrates supported Markdown commands to `source-command-*` skills; it rejects `$ARGUMENTS`, numbered argument placeholders, template braces, inline shell expansion and `@` file tokens. Legacy plugin migration also caps each resulting skill at **4,000 bytes**. Consequently `build` and `constraints` are rejected for `$ARGUMENTS`, while `ship` exceeds the cap even before wrapping (its source is 4,601 bytes). Relying on import would silently lose required workflows. [Template restrictions](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/core-plugins/src/command_migration.rs#L418-L434), [plugin importer](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/core-plugins/src/command_migration/plugin.rs#L16-L53).

The importer runs only for legacy plugin packages; native schema-bearing agent plugins bypass it. It reads command paths from the selected manifest, otherwise defaults to root `commands/` and scans Markdown. Upstream’s selected `.codex-plugin/plugin.json` has no `commands` field, and its root command files are TOML: the current Codex package does not convert `.claude/commands/`. [Installation gate](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/core-plugins/src/store.rs#L634-L642), [manifest command paths](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/core-plugins/src/manifest.rs#L209-L229), [upstream Codex manifest](https://github.com/addyosmani/agent-skills/blob/2686b620fc1fed2e8f60c704839c766b8594c6b6/.codex-plugin/plugin.json).

## Minimum conversion requirements

1. **Keep the existing workflow skills; add nine focused entry skills**, reusing their content instead of writing new engineering procedures. This gives **34 discoverable skills** at this snapshot. Use `skills/<command-stem>/SKILL.md` with the stem as `name` and a short, quoted `description`. The native loader validates a maximum 64-character base name. [Skill parser](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/skills/src/parser.rs#L4-L96).
2. **Keep host actions distinct from skill names.** Document `$plan` and `$review` as skills; Codex’s `/plan` and `/review` remain built-in host actions. The plugin applies a namespace, so `build` becomes `addyosmani-skills:build`; standalone installations can expose `$build`. All nine stems are distinct from the existing 25. Duplicate names are not merged: use the selector/file path or plugin-qualified name for disambiguation. Do not write a colon into base frontmatter or assume the old `agent-skills:` namespace. [Host slash commands](https://learn.chatgpt.com/docs/reference/slash-commands), [namespace source](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/ext/skills/src/loader/namespace.rs#L11-L26), [discovery and duplicate names](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills).
3. **Replace template arguments with caller-text inputs.** Examples: `$build`, `$build auto`, `$build all`, `$constraints check`, `$constraints guard`, `$constraints ratchet`. Define those modes in the body. Skills supply instructions rather than the deprecated prompt placeholder runtime; do not leave `$ARGUMENTS` expecting expansion. Optional explicit-only routing is `policy.allow_implicit_invocation: false` in `agents/openai.yaml`, not Claude’s `disable-model-invocation` frontmatter. [Skill policy loader](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/ext/skills/src/loader/metadata.rs#L33-L57), [policy semantics](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/skills/src/model.rs#L22-L28).
4. **Use the consuming project’s instructions and actual tools.** Read applicable `AGENTS.md`/overrides; for constraints write the Codex instruction pointer there. Do not overwrite the consuming project’s instructions with upstream’s contributor `AGENTS.md`, preload the meta-router, or hard-code a nonexistent `Skill`/`Agent` tool. Underlying browser setup uses Claude `.mcp.json`; give Codex setup for the same optional MCP capability. Missing metrics/tools must remain visible. [AGENTS discovery](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [upstream scope/router guidance](https://github.com/addyosmani/agent-skills/blob/2686b620fc1fed2e8f60c704839c766b8594c6b6/docs/codex-setup.md), [browser workflow](https://github.com/addyosmani/agent-skills/blob/2686b620fc1fed2e8f60c704839c766b8594c6b6/skills/browser-testing-with-devtools/SKILL.md#L24-L44).
5. **Adapt persona calls deliberately.** `ship` needs three independent concurrent Codex subagents and a main-agent merge; `webperf` needs one. Pass packaged persona instructions in each task, scope reviewers to reports and prohibit nested persona orchestration. Do not assume Claude `subagent_type` or `.claude/agents/` override priority exists. Codex custom agents are TOML under `.codex/agents/` or `~/.codex/agents/`; a skills-only bundle can use ordinary subagents without installing custom agent configurations. [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents), [agent-role file discovery](https://github.com/openai/codex/blob/01fc69f4026735edfdf6789820549727a4867b11/codex-rs/agent-roles/src/discovery.rs#L9-L51).
6. **Ship the resource closure of each selected skill.** skills.sh copies a selected skill directory, not its siblings or repository root. A mandatory “invoke another skill” therefore needs a packaged local reference/fallback or an explicit, detectable installation prerequisite. Reuse source workflow text as generated local references if standalone command installation must work; do not create separately hand-maintained copies. Bundle `ship`’s three [personas](https://github.com/addyosmani/agent-skills/tree/2686b620fc1fed2e8f60c704839c766b8594c6b6/agents) and `webperf`’s fourth persona with the appropriate entry. Rewrite package-resource links relative to the installed skill directory, while leaving user-project artifact paths relative to the user’s project. **Eleven existing skills also reference `../../references/`**, and `idea-refine` hard-codes `skills/idea-refine/scripts/idea-refine.sh`; address these portability gaps in the edition’s packaging. [Selected-directory installation](https://github.com/vercel-labs/skills/blob/3694740352eeef5cdd689af694c485f1ff62eec3/src/installer.ts#L352-L390), [root references](https://github.com/addyosmani/agent-skills/tree/2686b620fc1fed2e8f60c704839c766b8594c6b6/references), [idea helper invocation](https://github.com/addyosmani/agent-skills/blob/2686b620fc1fed2e8f60c704839c766b8594c6b6/skills/idea-refine/SKILL.md#L19-L24). Bundled references should not be named `SKILL.md`, and raw source snapshots should not add duplicate discovery entries. [Installer discovery](https://github.com/vercel-labs/skills/blob/3694740352eeef5cdd689af694c485f1ff62eec3/src/skills.ts#L254-L332).
7. **Preserve attribution and the MIT notice.** Record upstream SHA/path for derived entries and identify this repository as an adaptation. Keep Addy Osmani’s copyright and the complete permission notice with substantial copied text; include a `LICENSE` inside each independently installable skill so the notice travels through skills.sh. [Upstream license](https://github.com/addyosmani/agent-skills/blob/2686b620fc1fed2e8f60c704839c766b8594c6b6/LICENSE).

## Existing checks and concrete acceptance

The upstream snapshot passed `node scripts/validate-commands.js` (**9 commands, zero errors**) and `node scripts/validate-skills.js` (**25 skills, zero errors/warnings**). These checks validate upstream formats; they do not prove the Codex conversion, installed paths or behavior. The [artifact validator](https://github.com/addyosmani/agent-skills/blob/2686b620fc1fed2e8f60c704839c766b8594c6b6/scripts/validate-artifact-paths.js) guards producers/consumers but skips absent files and does not yet include the nine generated entry skills.

A minimal conversion check should establish:

- Source command stems equal the nine entry-skill names, with no omissions, duplicates or unexpected command entries; all 25 existing workflows remain discoverable.
- Both installation routes expose the same 34 workflows; a selected entry can read every mandatory local reference, persona, script and license after installation, including from a different working directory.
- Converted entry text contains no unresolved command placeholders, old plugin-qualified calls, required Claude tool calls or package paths accidentally resolved in the user’s project.
- Behavior checks cover default/`auto`/`all` build modes, the three constraints subcommands, existing-plan protection and source-to-plan-to-build artifact continuity, including designated spec/tracker conventions; `ship` collects actual independent reports, reports unavailable reviewers as incomplete and enforces rollback; severity normalization preserves mandatory fixes; Quick webperf fabricates no metrics and Deep mode records sources.
- Conversion is repeatable at a pinned upstream SHA and flags new/renamed commands or unsupported constructs instead of silently dropping them. Existing upstream validators remain useful as source checks.

## Conservative adaptation defaults

These compatibility conflicts can be resolved conservatively without adding maintainer decisions:

- **Preserve independent concurrent review.** `ship` mentions a sequential fallback but later forbids sequential fan-out. Preserve its actual independent reports and main-agent merge. If the necessary delegation is unavailable or fails, report the review as incomplete and fail visibly; do not invent completed reviewers or a GO verdict. A degraded workflow requires a later explicit maintainer authorization. [Ship contract](https://github.com/addyosmani/agent-skills/blob/2686b620fc1fed2e8f60c704839c766b8594c6b6/.claude/commands/ship.md).
- **Normalize severity without demoting obligations.** Keep Critical as Critical, map Required to Important with an explicit mandatory status, and map Optional/Nit to Suggestion. In ship synthesis, unresolved mandatory fixes remain blockers; an Important display label must not turn a required fix into an optional recommendation. [Command labels](https://github.com/addyosmani/agent-skills/blob/2686b620fc1fed2e8f60c704839c766b8594c6b6/.claude/commands/review.md), [reviewer obligations](https://github.com/addyosmani/agent-skills/blob/2686b620fc1fed2e8f60c704839c766b8594c6b6/agents/code-reviewer.md#L49-L63).
- **Honor target-project instructions and declared artifacts.** User and applicable harness/project instructions take precedence over packaged skill defaults. A designated tracker replaces `tasks/todo.md`; an established spec system controls its own format/location. This precedence is a harness requirement, not a new user preference. Keep `tasks/plan.md` as the upstream default plan document and record declared alternatives so producers and consumers agree. When module selection or a spec path is ambiguous, stop with the precise missing selection rather than inventing requirements, guessing a module or duplicating artifacts. [AGENTS discovery](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [tracker conventions](https://github.com/addyosmani/agent-skills/blob/2686b620fc1fed2e8f60c704839c766b8594c6b6/skills/planning-and-task-breakdown/SKILL.md#L143-L164), [external spec systems](https://github.com/addyosmani/agent-skills/blob/2686b620fc1fed2e8f60c704839c766b8594c6b6/skills/spec-driven-development/SKILL.md#L151-L156).

Format, baseline inventory and compatibility requirements are established. No production code was implemented. [Choose upstream ownership and the sync reliability contract](https://github.com/Qiuyi-Hong/addyosmani-skills/issues/5) remains scoped to ownership/import policy and sync reliability; these technical defaults do not expand that ticket. No additional subjective fidelity decision was found that prevents specification.
